# Полный промт для создания frontend

Скопируй весь текст ниже и отправь его ИИ, который будет создавать frontend. Это только техническое задание. Не пропускай пункты и не сокращай требования без разрешения владельца проекта.

---

Ты должен создать полностью готовый frontend для интернет-магазина компьютеров, ноутбуков, комплектующих и сборок ПК.

Объясняй свою работу очень простыми словами. Представь, что проект будет читать начинающий разработчик. Не используй сложную архитектуру без необходимости. Если добавляешь файл, коротко объясни, зачем он нужен.

## 1. Главная задача

Создай отдельный frontend-проект, который подключается к уже готовому Django REST Framework backend через API.

Frontend и backend должны находиться в отдельных папках и запускаться отдельно. Не переписывай backend и не копируй Django-код во frontend.

Frontend должен позволять пользователю:

- зарегистрироваться и войти;
- просматривать каталог товаров;
- искать, фильтровать и сортировать товары;
- открывать подробную карточку товара;
- добавлять товары в избранное;
- добавлять до четырёх товаров в сравнение;
- оставлять отзывы;
- добавлять товары в корзину;
- менять количество товара в корзине;
- удалять товар из корзины;
- очищать корзину;
- оформлять заказ;
- просматривать свои заказы;
- собирать собственный компьютер;
- проверять совместимость деталей;
- сохранять сборки;
- получать рекомендацию ноутбука;
- получать автоматическую рекомендацию сборки ПК;
- смотреть собранный компьютер в интерактивном 3D;
- раздвигать детали компьютера в режиме exploded view;
- выбирать деталь и читать информацию о ней;
- управлять 3D-моделью мышью, касанием и, как дополнительной функцией, жестами через камеру.

Менеджер и администратор должны получить дополнительные элементы управления согласно своей роли.

## 2. Технологии

Используй понятный современный стек:

- React;
- Vite;
- JavaScript, если TypeScript заметно усложнит проект;
- React Router для переходов между страницами frontend;
- Axios для API-запросов;
- обычный CSS, CSS Modules или один простой UI-подход;
- Three.js через React Three Fiber для 3D;
- Drei для стандартных 3D-контролов и вспомогательных компонентов;
- Framer Motion для плавных интерфейсных анимаций;
- MediaPipe Hands только для дополнительного управления жестами через камеру.

Не добавляй Redux, сложные state machines, микрофронтенды и другие тяжёлые технологии, если проект нормально работает без них. Для глобального состояния достаточно React Context или небольшого простого store.

React Router относится только к навигации frontend. Не меняй ручные Django API URLs и не добавляй DRF router в backend.

## 4. Структура страниц

Создай следующие страницы.

### Главная страница

На главной странице должны быть:

- красивый первый экран;
- короткое описание магазина;
- кнопки перехода в каталог и конструктор ПК;
- интерактивный или демонстрационный 3D-компьютер;
- популярные категории;
- несколько товаров из реального API;
- блок о проверке совместимости;
- блок о рекомендациях;
- преимущества магазина;
- footer с навигацией.

Не показывай выдуманные товары, если backend доступен. Все карточки товаров загружай из API.

### Каталог

Каталог должен содержать:

- список или сетку товаров;
- строку поиска;
- фильтр по категории;
- фильтр по типу товара;
- фильтр по бренду;
- минимальную и максимальную цену;
- переключатель «только в наличии»;
- сортировку по названию, цене и количеству;
- pagination;
- кнопку сброса фильтров;
- понятное состояние, когда товары не найдены.

Фильтры должны отправляться в backend как query parameters. Не загружай весь каталог для фильтрации только на стороне браузера.

### Карточка товара

Покажи:

- название;
- изображение;
- бренд;
- категорию;
- тип товара;
- цену;
- остаток;
- описание;
- технические характеристики;
- средний рейтинг;
- количество отзывов;
- список отзывов;
- форму нового отзыва для авторизованного пользователя;
- кнопки «Добавить в корзину», «В избранное» и «Сравнить»;
- понятное сообщение, если товара нет в наличии.

Пользователь не должен иметь возможность заказать количество больше остатка.

### Регистрация и вход

Регистрация должна содержать поля:

- username;
- email;
- phone;
- password;
- подтверждение password только на frontend.

Форма входа должна содержать username и password.

Показывай ошибки каждого поля понятным текстом. После успешного входа возвращай пользователя на предыдущую страницу или в профиль.

### Профиль

Покажи:

- username;
- email;
- phone;
- avatar;
- role;
- форму изменения доступных данных;
- переход к заказам;
- переход к сохранённым сборкам;
- кнопку logout.

Пользователь не может сам изменить свою role.

### Избранное

Покажи только избранные товары текущего пользователя. Добавь удаление товара и переход в карточку. Не создавай повторные записи.

### Сравнение

Разреши сравнивать максимум четыре товара.

Покажи товары в понятной таблице:

- изображение;
- название;
- цена;
- бренд;
- тип;
- основные характеристики;
- рейтинг;
- наличие.

Различающиеся характеристики визуально выделяй. Добавь удаление товара из сравнения.

### Корзина

Покажи:

- товар;
- цену;
- количество;
- item total;
- subtotal;
- общее количество товаров;
- удаление позиции;
- изменение количества;
- очистку корзины;
- кнопку оформления заказа.

Backend сам считает итоговую цену. Не доверяй цене, сохранённой только во frontend.

### Оформление заказа

Форма должна содержать:

- first name;
- last name;
- phone;
- city;
- address.

Перед отправкой покажи состав корзины и итоговую сумму. После успешного заказа покажи номер заказа и очистившуюся корзину. Если остаток изменился, покажи ошибку backend понятным языком.

### Мои заказы

Покажи:

- номер заказа;
- дату;
- статус;
- итоговую сумму;
- позиции заказа;
- количество и сохранённую цену каждой позиции.

Добавь визуальные метки статусов: pending, confirmed, delivered и cancelled.

### Конструктор ПК

Сделай пошаговый конструктор:

1. CPU.
2. GPU.
3. Motherboard.
4. RAM.
5. Storage.
6. PSU.
7. Case.

На каждом шаге показывай только реальные товары из backend. Показывай текущую цену сборки и выбранные компоненты.

Перед сохранением отправляй детали в endpoint проверки совместимости. Если есть ошибки, покажи их рядом с проблемными деталями. Не сохраняй несовместимую сборку.

Добавь:

- замену выбранной детали;
- удаление выбранной детали;
- сброс сборки;
- сохранение сборки авторизованным пользователем;
- переход в 3D-просмотр;
- кнопку добавления деталей сборки в корзину, если это возможно через текущий API.

### Сохранённые сборки

Пользователь видит только свои сборки. Для каждой сборки покажи:

- название;
- компоненты;
- total price;
- результат совместимости;
- кнопку редактирования;
- кнопку удаления;
- кнопку 3D-просмотра.

### Рекомендация ноутбука

Создай понятную форму:

- budget;
- good screen;
- long battery;
- gaming;
- programming.

Результат должен прийти только из backend. Покажи до пяти товаров, score и reasons. Не придумывай ноутбуки во frontend.

### Рекомендация ПК

Форма должна содержать:

- budget;
- gaming;
- programming.

Покажи рекомендованные компоненты, total price и результат совместимости. Если сборку создать невозможно, покажи сообщение backend.

### Панель Manager/Admin

Показывай эту часть только пользователям с нужной role.

Manager может:

- создавать товары;
- изменять товары;
- менять stock;
- просматривать все заказы;
- менять статус заказа.

Admin может всё, что Manager, а также:

- удалять товары;
- просматривать пользователей;
- менять role пользователя;
- включать и отключать пользователя.

Frontend должен скрывать запрещённые кнопки, но настоящая безопасность всё равно проверяется backend.

## 5. Подключение к backend

Backend локально работает по адресу http://127.0.0.1:8000.

Для разработки настрой frontend так, чтобы API-запросы на `/api` передавались Django-серверу. Адрес backend должен храниться в переменной окружения frontend, чтобы его можно было поменять без переписывания компонентов.

Если frontend и backend запускаются на разных доменах без proxy, сообщи, что на backend потребуется разрешить CORS для адреса frontend. Самовольно не переписывай backend в рамках frontend-задачи.

Используй следующие API endpoints:

- POST `/api/register/` — регистрация;
- POST `/api/login/` — access и refresh tokens;
- POST `/api/token/refresh/` — обновление access token;
- POST `/api/logout/` — logout и blacklist refresh token;
- GET/PATCH `/api/profile/` — профиль;
- GET/POST `/api/categories/` — категории;
- GET/POST `/api/products/` — товары;
- GET/PATCH/DELETE `/api/products/{id}/` — один товар;
- GET/POST `/api/reviews/` — отзывы;
- GET/PATCH/DELETE `/api/reviews/{id}/` — один отзыв;
- GET/POST `/api/wishlist/` — избранное;
- DELETE `/api/wishlist/{id}/` — удалить из избранного;
- GET/POST `/api/compare/` — сравнение;
- DELETE `/api/compare/{id}/` — удалить из сравнения;
- GET `/api/carts/` — корзина;
- GET/POST `/api/cart-items/` — позиции корзины;
- PATCH/DELETE `/api/cart-items/{id}/` — изменить или удалить позицию;
- DELETE `/api/cart/clear/` — очистить корзину;
- GET/POST `/api/orders/` — мои заказы и создание заказа;
- GET `/api/orders/{id}/` — один заказ;
- PATCH `/api/orders/{id}/status/` — изменение статуса Manager/Admin;
- GET/POST `/api/pc-builds/` — сборки пользователя;
- GET/PATCH/DELETE `/api/pc-builds/{id}/` — одна сборка;
- POST `/api/compatibility/check/` — проверка совместимости;
- POST `/api/recommendations/laptops/` — рекомендация ноутбука;
- POST `/api/recommendations/pc/` — рекомендация ПК;
- GET `/api/admin/users/` — пользователи для Admin;
- GET/PATCH `/api/admin/users/{id}/` — управление пользователем;
- GET `/api/admin/orders/` — все заказы Manager/Admin.

Перед реализацией проверь актуальную схему по Swagger backend: http://127.0.0.1:8000/swagger/

## 6. JWT-авторизация

Создай один понятный модуль для API-запросов.

Требования:

- добавляй access token в заголовок Authorization как Bearer token;
- при истечении access token один раз пробуй получить новый через refresh token;
- повторяй исходный запрос после успешного обновления;
- если refresh token тоже недействителен, очищай авторизацию и перенаправляй на страницу входа;
- logout должен вызывать backend, а затем удалять локальные tokens;
- защищённые страницы не должны открываться гостю;
- страницы Manager/Admin должны проверять role;
- не показывай password и tokens в интерфейсе или console.

Сделай восстановление пользовательской сессии после перезагрузки страницы.

## 7. Состояния интерфейса

Для каждого API-блока обязательно добавь:

- loading;
- success;
- empty state;
- validation error;
- server error;
- network error;
- кнопку повторной загрузки там, где это полезно.

Не оставляй пустой белый экран. Не показывай пользователю сырой stack trace или непонятный объект ошибки.

Используй skeleton loaders для каталога и карточек. Для действий добавления и удаления показывай небольшой toast.

Перед опасными действиями, например удалением товара, сборки или очисткой корзины, показывай подтверждение.

## 8. 3D-просмотр компьютера

Это одна из главных функций frontend.

Создай отдельную страницу 3D-просмотра сборки.

В обычном состоянии пользователь видит собранный компьютер. Он может:

- вращать модель;
- приближать и отдалять;
- перемещать камеру;
- нажимать на детали;
- подсвечивать выбранную деталь;
- скрывать корпус;
- возвращать камеру в начальное положение;
- запускать сборку и разборку;
- включать exploded view.

### Exploded view

При включении exploded view компоненты должны плавно разлетаться в разные стороны, но оставаться логично расположенными вокруг корпуса.

Пример направления:

- боковые панели корпуса уходят в стороны;
- GPU выдвигается наружу;
- CPU и cooler поднимаются;
- RAM раздвигается;
- PSU опускается или выдвигается назад;
- storage смещается в отдельную сторону;
- motherboard немного выдвигается из корпуса.

Переход должен быть плавным и обратимым. Добавь общий progress разборки, чтобы анимацию можно было проигрывать вперёд и назад.

### Информация о детали

При клике на деталь:

- останови автоматическую анимацию;
- подсвети деталь;
- слегка отодвинь её от остальных;
- открой боковую информационную панель;
- покажи название, тип, бренд, цену, изображение и характеристики;
- добавь кнопки перехода к карточке товара и добавления в корзину;
- покажи линию или подпись между деталью и панелью, если это не ухудшает мобильный интерфейс.

### 3D-ресурсы

Backend пока не содержит отдельное поле для ссылки на GLB/GLTF-модель. Поэтому:

- храни 3D-файлы в папке assets/public frontend;
- создай простой конфигурационный файл соответствия типа компонента и 3D-модели;
- используй одну качественную базовую модель для каждого типа детали;
- реальные название, цена и характеристики всегда должны приходить из backend;
- если 3D-файл отсутствует, покажи понятную геометрическую заглушку, а не ломай страницу;
- подготовь архитектуру так, чтобы позже можно было принять URL 3D-модели от backend.

Оптимизируй модели и текстуры. Добавь экран загрузки 3D-сцены и fallback для устройств без WebGL.

## 9. Управление жестами через камеру

Это дополнительный режим. Обычное управление мышью и касанием должно работать всегда, даже если камера недоступна.

Требования:

- не включай камеру автоматически;
- покажи отдельную кнопку «Управление жестами»;
- перед запросом разрешения коротко объясни, зачем нужна камера;
- видео обрабатывай локально в браузере;
- не отправляй видео на backend;
- покажи индикатор, когда камера активна;
- добавь кнопку немедленного отключения камеры;
- при отказе в разрешении спокойно верни обычное управление.

Пример жестов:

- движение открытой ладони влево и вправо вращает модель;
- движение ладони вверх и вниз меняет угол обзора;
- pinch выбирает деталь;
- разведение двух рук включает или усиливает exploded view;
- сведение рук возвращает детали в собранное состояние;
- закрытая ладонь или отдельная экранная кнопка останавливает управление.

Добавь небольшую обучающую подсказку с рисунками или простыми анимациями жестов. Сделай сглаживание движений, чтобы модель не дёргалась.

- отсутствие лишних повторных API-запросов;
- понятный fallback, если 3D слишком тяжёлый для устройства.

## 13. Правила данных

- Не придумывай товары, цены, остатки, заказы и пользователей.
- Основные данные всегда бери из backend.
- Не считай окончательную цену заказа только во frontend.
- Не разрешай пользователю менять role.
- Не показывай административные действия обычному пользователю.
- Не сохраняй password.
- Не отправляй данные камеры на сервер.
- Не сохраняй несовместимую сборку.
- Не разрешай сравнивать больше четырёх товаров.
- Не разрешай добавить количество больше stock.
- Не используй настоящий AI или внешний LLM для рекомендаций: готовый backend уже содержит обычную логику подбора.

## 14. Структура frontend-проекта

Сделай структуру понятной для новичка. Отдельно храни:

- страницы;
- общие компоненты;
- API-функции;
- авторизацию;
- стили;
- 3D-компоненты;
- 3D-assets;
- hooks;
- небольшие утилиты;
- конфигурацию.

Не создавай пустые папки и файлы «на будущее». Каждый созданный файл должен использоваться.

## 15. Проверки

Перед завершением обязательно проверь:

- frontend устанавливается без ошибок;
- development server запускается;
- production build собирается;
- нет ошибок в console;
- API base URL меняется через environment variable;
- регистрация работает;
- login, refresh и logout работают;
- защищённые страницы закрыты от гостя;
- роли правильно ограничивают интерфейс;
- каталог загружается из backend;
- поиск, фильтры и pagination работают;
- карточка товара работает;
- отзывы работают;
- избранное работает;
- сравнение ограничено четырьмя товарами;
- корзина считает суммы из ответа backend;
- заказ создаётся;
- заказы отображаются;
- конструктор проверяет совместимость;
- сборка сохраняется;
- рекомендации используют backend;
- 3D открывается;
- exploded view собирается обратно;
- выбор детали показывает информацию;
- сайт работает без камеры;
- жесты корректно отключаются;
- мобильная версия не ломается;
- страница обновляется без ошибки маршрута.

Добавь несколько понятных frontend-тестов для самых важных сценариев: авторизация, каталог, корзина и защищённый маршрут. Не усложняй тестовую архитектуру.

## 17. Порядок выполнения

Работай по этапам:

1. Создай каркас frontend.
2. Настрой стили и маршруты страниц.
3. Настрой API и JWT.
4. Создай регистрацию, login и профиль.
5. Создай каталог и карточку товара.
6. Создай отзывы, избранное и сравнение.

- не отправляй `.env`, tokens, пароли, `node_modules` и build-файлы в GitHub.

## 18. Критерий полной готовности

Работа считается законченной только тогда, когда новый пользователь может:

1. Зарегистрироваться.
2. Войти.
3. Найти товар.
4. Открыть карточку.
5. Добавить товар в избранное и сравнение.
6. Добавить товар в корзину.
7. Оформить заказ.
8. Посмотреть заказ в профиле.
9. Собрать совместимый ПК.
10. Сохранить сборку.
11. Открыть сборку в 3D.
12. Раздвинуть детали.
13. Нажать на деталь и увидеть информацию.
14. При желании включить управление жестами.

Manager и Admin должны видеть только разрешённые им инструменты. Все данные должны приходить из существующего Django backend. Интерфейс должен быть красивым, понятным, адаптивным и устойчивым к ошибкам API.

- список подключённых API endpoints;
- команды запуска;

- какие 3D-assets используются;
- что осталось только для будущего улучшения, если что-то невозможно из-за отсутствующих данных или 3D-моделей.
